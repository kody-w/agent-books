Chapter 10 — Building a Real System End to End

In this chapter: compose two capabilities over real files, replay only step 1 with later evidence, and check exact data movement rather than prose plausibility.

10.1 Run the system

Run python3 brainstem/examples/10_system.py. It prints an archive and both draft versions. This shorter executable form makes the acceptance checks visible:

import sys
sys.path.insert(0, "brainstem/examples")
from mini_loop import FIXTURES, system

result = system(FIXTURES / "chat.txt", FIXTURES / "later.txt")
assert result["review"]["data_slush"]["draft"] == result["original"]["data_slush"]["draft"]
assert result["review"]["data_slush"]["sent"] is False
assert "Monday" not in result["original"]["summary"]
assert "Monday" in result["replayed"]["summary"]
assert result["events_after_replay"] == 3
print(result["replayed"]["summary"])

The same task appears in the companion chapter: read a chat transcript, draft a follow-up, hand its result to a second step, and replay step 1 with a later file. Both use the same synthetic library discussion and deadline correction.

10.2 Trace the four boundaries

First, file I/O reads the chat into a string. The agent receives text, not a machine-specific path. That makes the call independently recordable.

Second, DraftFollowUp produces a draft and source digest. The system checks success before accessing data_slush. It does not report an empty draft as success.

Third, ReviewDraft receives the exact draft field. It returns a review-ready artifact with sent: false; no mail integration exists.

Fourth, replay copies only the first call's arguments and appends the later file's contents. It adds one new draft event. The reviewer is not re-executed, and the old review continues to refer to the old draft. If a human accepts the revised draft, a new review should be recorded rather than silently updating the earlier one.

10.3 The draft is intentionally modest

The template preserves evidence rather than deciding which deadline wins. A semantic replacement belongs behind perform(). Evaluate commitments, conflicting dates, unsupported promises, and draft-only behavior separately from the interface and handoff checks.

10.4 Make the archive durable

Redirect the command's JSON or call MiniLoop.save() to retain events and their implementation digest; preserve the matching revision too. Real transcripts belong in access-controlled storage, not this public book's static endpoint.

The local tests additionally run all ten programs, check replay immutability and source mismatch refusal, and exercise the complete flow with independent temporary files. These checks cover deterministic mechanics.

The real chapter 10 turns additionally ran through the copied production /chat: a real model called the draft tool, then the reviewer with the identical draft, then only the draft tool with the later evidence. The runner asserts that Monday appears only in the revised draft, the handoff is exact, nothing is sent, and replay does not execute the reviewer. This is a caller- initiated selected-step re-execution, not a built-in runtime rewind command.

10.5 Exercises

Exercise 10-1. Use two files you create in a temporary directory. Change the later deadline and verify that only the replayed draft changes.

Exercise 10-2. Add a review of the revised draft as a fourth event. Preserve both review versions and make their source identities explicit.

Exercise 10-3. Replace the drafting template with a model-backed implementation. Keep mechanical checks separate from semantic quality and live-access checks.

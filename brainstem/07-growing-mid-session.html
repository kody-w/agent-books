Chapter 7 — Growing Mid-Session

In this chapter: load trusted code into a running registry, describe the LearnNew cycle, and distinguish installation from discovery.

7.1 Add a capability

Run python3 brainstem/examples/07_growth.py.

import sys
sys.path.insert(0, "brainstem/examples")
from mini_loop import MiniLoop, SOURCE, load_trusted_file

loop = MiniLoop()
del loop.tools["ReviewDraft"]
assert "ReviewDraft" not in loop.tools
loop.register(load_trusted_file(SOURCE))
print(loop.call("ReviewDraft", {"draft": "Library follow-up draft"})["summary"])

The registry changes while the caller object stays alive. We remove an already known capability first only to make the before-and-after boundary visible. The file is the reviewed, checked-in agent.py; the example does not download, generate, or execute arbitrary remote code.

7.2 The learning cycle

The installed agents/rar_rapp_learn_new_agent.py:344–442 writes a generated *_agent.py beside LearnNew itself, attempts an import, and reports hot_loaded separately from write success. _hot_load_agent() (lines 845–886) imports and registers a module; it does not add a tool to the current /chat request's local registry. brainstem.py:1836–1864,2274–2284 scans and instantiates agent files on every new request. No directory watcher is needed: the next turn gets a fresh inventory. Within the current turn the original inventory remains in use.

Changing AGENTS_PATH alone is insufficient to redirect LearnNew's writes: self.agents_dir = Path(__file__).parent. The live runner copies LearnNew into its temporary agents directory rather than importing it from the real installation.

The real chapter 7 fixture records LearnNew creating BookUpper with hot_loaded: true, followed by a separate model turn calling BookUpper. Creation and next-turn discovery worked. The requested uppercase behavior did not: the tool returned Processed by BookUpper: library instead of LIBRARY. Its recorded source contains the stock fallback body. LearnNew invokes copilot --message (lines 780–807); the installed CLI rejects --message with exit 1. LearnNew silently substitutes its scaffold on that path. Do not treat its creation-success message as proof of the requested semantics.

7.3 Installation is not discovery

Creating Python code, importing it, adding an instance to a registry, and exposing its declaration to a model are four different actions. Searching a catalog of existing tools changes visibility, not implementation. Reloading a file can change implementation even when its name stays the same.

Track both the declaration and implementation identity when you care about replay. A repeated tool name is not proof that the same code ran. MiniLoop.register() rejects duplicate names rather than silently replacing an existing instance, because an accidental overwrite would make the demonstration's history ambiguous.

The caller should not need a special case for each learned agent. It should need a general registry refresh and a normal call interface. New per-agent branches in the host are a sign that implementation details are leaking across the boundary.

7.4 Import is execution

Python executes module-level code during import. Compilation proves syntax, not safety. A generated file can read credentials before its class is even instantiated. Review and permission checks therefore belong before loading, not after the first tool result.

For an actual learning system, stage the file, validate its public declaration, run bounded tests in an appropriate isolation boundary, approve its permissions, then publish it to the active registry. Do not label code safe merely because a model wrote it or its filename ends in _agent.py.

The miniature example intentionally omits an automatic code-generation facility. Its purpose is to show capability availability without pretending that arbitrary code generation has become harmless.

Chapter 9 — Hosts and Portability

In this chapter: expose a Python handler through SDK MCP and compare host contracts without assuming every surface runs the same package unchanged.

9.1 Wrap the handler

Run python3 claude/examples/09_hosts.py for the live Agent SDK invocation. This complete declaration is importable without making a model request:

from claude_agent_sdk import create_sdk_mcp_server, tool

@tool("review_draft", "Prepare a draft for human review; never send.", {"draft": str})
async def review_draft(args):
    return {"content": [{"type": "text", "text": args["draft"]}],
            "structuredContent": {"draft": args["draft"], "sent": False}}

server = create_sdk_mcp_server(name="book", tools=[review_draft])
print(server["type"])

The SDK creates an in-process MCP server. The live example passes it under the key book and allows mcp__book__review_draft. That name derives from the server key and tool name, not from an arbitrary Python variable. Custom tools and naming.

9.2 API, Code, and SDK

The Messages API leaves the client loop and client-tool implementation with the application. Claude Code provides an existing interactive host. The Agent SDK provides query() for one-shot work and ClaudeSDKClient for multi-turn applications, plus configurable tools, hooks, and session handling. Tool use, Python SDK.

Application guidance: share domain logic, not assumptions about transport. The same draft function can serve an API handler or an SDK MCP wrapper, but its declaration and result envelope must match the chosen host.

9.3 Managed Agents

Managed Agents provides built-in sandbox tools and custom-tool declarations. Custom calls are emitted as events; an application or worker runs the implementation and posts the corresponding result. A self-hosted worker can reach internal services within its configured network without exposing an inbound MCP endpoint publicly. Managed tools, self-hosted workers and custom tools.

The fetched documentation labels Managed Agents beta. Its hosted sessions and worker configuration are not the same runtime as a local SDK process. Application guidance: verify event delivery, tool availability, permission policy, and data retention for the actual deployment rather than porting by name alone. Managed Agents feature contract.

9.4 Cowork, chat skills, and Chrome

Cowork uses the same agentic architecture for knowledge work and now runs sessions in the cloud, with local access mediated through the desktop app when needed. Closing a laptop is not the same lifecycle boundary as a local process exit. Cowork execution.

claude.ai skills can be enabled, uploaded, shared, or provisioned subject to account and organization controls. The current guide also documents skills syncing into Claude Code for the same signed-in account on supported versions. This is a real reuse path, but host-specific frontmatter and resource behavior still matter. Skills in Claude, Code skill portability.

Claude Code's Chrome integration uses the Claude in Chrome extension and the browser's signed-in state. Browser actions are visible, site permissions matter, and login or CAPTCHA can require manual intervention. API-key authentication alone does not enable this browser integration. Chrome prerequisites and permissions.

9.5 Exercise the destination

Application guidance: test each host separately for filesystem, networking, credentials, package availability, persistence, approval, and failure handling. The SDK wrapper above proves a declaration can be constructed; only its live invocation proves authenticated tool execution in that environment.
